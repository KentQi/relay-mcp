# relay-discipline — 写代码时的纪律,每条都有执法者

本技能是 `relay-protocol` 的补充:protocol 负责"怎么交接",本技能负责"接过来之后怎么写"。
原则来自工程实践(含 ub-mode 的三段式:先跑通 → 再做对 → 留下证据),但每条都映射到 relay
的机检点——**没有执法者的规则不写进来**。

## 第一阶段:First make it work(先跑通)

### 最小可用改动

- 一次只解决一个问题;能一行解决就不写三层抽象。
- 先让端到端路径通,再考虑结构。中间态允许不优雅,但必须可回退。
- 落点:`relay_claim` 的任务行 + `验收:` 一行可执行判定;改动范围写进 LOG 摘要。

### 红灯先行

- 先写下会失败的验收(失败测试 / `test:` 命令),确认它**因为预期原因**失败,再改代码。
- 没有诚实的验收就不要编一个假的:空洞验收(`true`、只 echo)比没有验收更糟。
- 落点:`验收: test:<失败测试路径>`;出场时 `relay_session_end` 会真的执行它,红则不提交。

### 数据形状先于逻辑

- 先把输入/输出的形状定死(字段、类型、边界),再写处理逻辑。
- 外部数据在边界解析一次;内部只信任已解析的结构。
- 落点:`manifest` 配置在 `src/config.mjs` 单一入口归一;非法值在边界拒绝(R2/R11 与路径校验)。

### 从第一性重设计,而不是打补丁

- 新需求与旧设计冲突时,先问"如果一开始就有它,我会怎么建",再分步交付。
- 同一前提的两个修法都失败时:**停下**,用一句话写下那个前提,再决定改前提还是改实现。
- 落点:连续 3 条任务会话没有完成 → R7 ERROR 停机,强制人类仲裁;不要继续换皮重试。

## 第二阶段:Then make it right(再做对)

### 修根因,不修症状

- 先复现,再改因;只把崩溃藏起来的 guard 不算修复。
- 失败信息里必须有"修复:"可执行指令,而不是"出错了"。
- 落点:`relay_verify` 每条失败都带 `修复:`;R10 事实行让"改了什么"可回放。

### 小步可验证

- 一个提交只做一件可独立验证的事;做完立刻验证,再开始下一件。
- 一个任务应当能在一个会话内完成;跨 3 个会话还没完成,说明任务太大,拆。
- 落点:TASKS 的任务行 + `验收:`;出场绿闸要求任务树与 controlRoot 双绿。

### 测行为,不测实现

- 测试从调用者的入口进、断言调用者能看到的结果。
- 如果所有函数都返回空值测试还能过,这个测试应当删掉。
- 落点:`acceptance.commands` 白名单可接外部质量门(CRAP、重复率、变异测试);relay 只编排,不内置。

### 结构可读

- 复杂度、重复率这类指标用外部工具量化,阈值写进验收命令;不靠"感觉还行"。
- 重构三步:先钉住行为(测试),再改结构,最后证明行为没变。
- 落点:质量门预设(见 README「质量门预设」),命令逐字符登记进 manifest 才会执行。

## 第三阶段:Practice(留下证据)

### 记录理由,而不只是动作

- 每个决定写"为什么",负结果写"试过什么、为什么不行"——这是给下一个模型的礼物。
- 落点:LOG 条目的 `摘要 / 负结果 / 交接提示`;`{{evidence}}` 模板变量让提交信息自带证据。

### 守住上下文预算

- 主线程只留结论;大块阅读交给检索(relay_recall → relay_get),不要把整份历史塞进对话。
- 不为"可能有用"付常驻成本:规则条文放 `relay_rules` / `relay://protocol`,按需读取。
- 落点:`tools/list` 有体积预算断言(smoke-budget);简报有字符预算(T015,超限告警不裁剪)。

### 清理要等人决策

- 过期 worktree 可以先报告;含未跟踪/ignored 内容(`.env`、`node_modules`、构建产物)的现场默认保留。
- 删除只走非强制的 `git worktree remove`;分支永远保留,合并是人的决定。
- 落点:`relay_worktree_cleanup`(默认 dry-run)、`relay_archive_log`(默认 dry-run)。

### 小步提交,证据随行

- 一个提交说清三件事:为什么改、改了什么、怎么证明(命令与结果)。
- 验收通过 ≠ 已合并:任务分支保持 `relay/T###` 未合并,由人 `git merge --no-ff`。
- 落点:`relay_session_end` 双提交 + 事实行 + `git log --grep "T### 完成"`。

## 自检清单(每次出场前)

1. `relay_verify { full: true }` 全绿,失败项按 `修复:` 处理完;
2. `验收:` 是真执行过的,不是文字描述;
3. LOG 写了负结果与交接,下一个会话不需要猜;
4. 没有为了变绿而删测试、改阈值、跳过断言;
5. 本次改动没有把规则条文塞回工具描述(上下文预算不反弹)。

> 这套纪律不替代判断力:规则与机检是下限,不是上限。真正拿不准时,停机问人,
> 比用同一前提连续试错更便宜。
