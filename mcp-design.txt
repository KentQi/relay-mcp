好，抛开一切现有工具和框架。从零推导。

# 第一步：公理

整个问题只建立在五条不可再约的事实上：

1. **无状态性**：模型是函数 `输出 = f(输入上下文)`。会话结束，记忆归零。模型之间不存在任何直接的信息通道。
2. **有限上下文**：上下文窗口有界且昂贵，注意力随长度衰减。无法把"一切"都塞给下一个模型。
3. **随机性**：模型输出是概率采样。单次出错率 ε > 0，接力 n 次后整体可靠性 ≈ (1-ε)ⁿ——**误差沿链条复利累积**。
4. **唯一共享介质**：所有模型都能访问的、持久的、带版本的、有原子语义的介质，只有**项目仓库**本身。
5. **代码是唯一不撒谎的状态**：任何"描述现状"的文字都可能与现实漂移；可执行 artifact 不会——测试要么过，要么不过。

# 第二步：六位专家独立推导

**专家一 · 分布式系统工程师**
"这不是新问题。把每个模型会话看成一个**彻底失忆的 worker 节点**，这就是经典的分布式状态复制问题。已知解法：append-only 事件日志 + 周期性快照——节点恢复时读快照、重放近期日志。并发写共享状态需要单写者或锁；任务必须幂等可重入。另外，会话边界必须对齐事务边界：**一次会话 = 一个原子提交，不允许'做了一半'的状态出仓**。"

**专家二 · 形式化验证专家**
"跨边界传递的信息只有两类：可机器检查的，和不可检查的。后者在多跳传递中必然漂移（公理 3）。唯一能把漂移归零的手段，是把信息编码进**可执行 artifact**。所以交接物不应该是'描述'，而应该是'判定'：一套绿灯（=已完成）加一盏红灯（=下一步）。接班者不需要相信任何文字，它只需要**运行**。"

**专家三 · 软件考古学家**
"人类干这件事干了几十年了：新人接手离职者的项目，没人交接。成功的项目有共性：代码自描述、测试能跑、提交历史讲清'为什么'、关键决策有记录。失败的共性：知识只存在某人脑子里。模型只是把这个人类问题推到极限——**它连'问前同事'这个选项都没有**。对待每一代模型，就该像对待一个永远不会开口说话的前任开发者。"

**专家四 · 可靠性工程师**
"串联系统 R = (1-ε)ⁿ，只有两条路：降 ε，或切断串联。切断的方法就是每轮**闭环归零**：执行→检测→修正→再检测，传感器读数不达标就不许交棒——这样误差无法跨轮传播。还需要一个**发散报警器**：连续 N 轮无进展即停机上报。最后，模型的多样性是免费的冗余资源：用不同模型做审查，比同模型自审更容易抓到错误，因为独立副本的故障不相关。"

**专家五 · 组织行为学家**
"这就是'永不见面、永不实时沟通'的极端异步团队。全远程公司的答案早已验证：书面文化、单一事实源、明确的完成定义、小步提交、异步评审。异步协作的瓶颈从来不是'写'，而是**对齐**——对齐靠把'什么叫完成'从人嘴里搬进仓库，而不是靠更多沟通。"

**专家六 · 信息论学者**
"交接 = 有限带宽（公理 2）+ 有噪声（公理 3）的信道。有噪声就需要冗余校验——**测试就是纠错码**。带宽有限就必须只传'最小充分统计量'：凡接收方能自己从仓库重算出来的信息，都不该占用信道传输——传了既浪费，又必然过期。"

# 第三步：汇合与分歧

六位专家互不知情，结论却收敛于四点：

| 汇合点 | 来源 |
|---|---|
| 仓库是唯一介质 → 仓库必须**自我说明** | 考古、分布式、组织 |
| 可执行验证优于一切文字 → **测试即交接协议** | 形式化、可靠性、信息论 |
| 只存"无法推导"的状态 → 最小状态 + 追加日志 | 分布式、信息论、考古 |
| 每轮闭环 + 发散报警 | 可靠性、组织 |

真正的分歧只有两处，如实列出：

- **并行要不要锁？** 分布式专家坚持单写者；组织学家认为任务按模块边界切得够小，冲突概率可忽略。→ 折中：默认串行，并行时按模块边界切分。
- **规范能否全部可执行化？** 形式化专家想全量编译成检查；考古学家指出"为什么这么设计"永远无法可执行化。→ 折中：规范强制分两层，承认第二层是概率性的并尽量压缩它。

# 第四步：最终完整建议

## 三条根本原则

**原则一 · 最小充分状态（MSS）**
只持久化**无法从仓库重新推导**的四样东西：意图、验收标准、决策的理由、下一步任务。一切"现状描述"都应该是运行时的生成物，而不是维护物——因为维护物必然漂移（公理 5），漂移比缺失更危险。

**原则二 · 无信任交接（Trustless Handoff）**
接班模型不信任任何文字声明，只信任可执行结果。因此交班模型的义务不是"写一份动人的总结"，而是：**留下全绿的验证套件，以及一个编码了下个任务的失败测试**。绿灯 = 已验证的领土，红灯 = 从这里开始。这是整条链上唯一能切断误差复利（公理 3）的机制。

**原则三 · 规范即检查（Norms as Checks）**
每一条规范，要么编译成机器可执行的检查，要么承认它只是概率性建议并把它压缩到最少。风格交给提交时的自动归一化（模型爱写什么风格都行，过闸时被格式化）；结构交给模板（正向：正确的路最好走）加结构测试（反向：违规即构建失败）；只有选型理由、禁区这类语义规范才留在文字层。

## 仓库形态：自举式仓库

不依赖任何 harness 去读任何特定文件——仓库本身就是说明书：

```
/START.md      ← 唯一入口，一页以内：这个仓库怎么读、每一步做什么
/SPEC.md       ← 意图：目标 + 可验证的验收标准（几乎不改）
/DECISIONS.md  ← 追加式决策日志：决定 + 理由 + 被否决的选项
/TASKS.md      ← 有序任务队列，每条附"完成判定"（哪条测试变绿）
/LOG.md        ← 追加式会话日志：做了什么、发现什么、留给下一个什么
verify         ← 一键运行全部检查（构建+测试+风格+结构）
```

`START.md` 是引导扇区。它对任何智能体只说三件事：先跑 `verify`；读 `TASKS.md` 顶部；按协议干活。

## 会话协议：任何模型、任何 harness，六步

1. **同步**：读 `START.md` → 运行 `verify` → 结果即真相（不看任何文字声称的现状）；
2. **认领**：标记 `TASKS.md` 顶部任务为进行中，`LOG.md` 追加一行；
3. **执行**：任务粒度以"一次会话内可完成并可验证"为上限（按池中**最弱**模型切）；
4. **自证**：`verify` 全绿才允许提交，否则原地修复；修不动就标记阻塞、写清原因、停机等人——**不绿不提交，提交即交接**；
5. **交棒**：追加 `LOG`；更新 `TASKS`；为下一个任务写下失败测试；
6. **发散检测**：日志显示连续 3 次会话无任务完成 → 停机，升级人类仲裁。

## 人类不可让渡的三件事

定义验收标准（语义权威）；仲裁阻塞与豁免（责任锚点）；定期抽查（概率层的最终防线）。人的开口成本最终退化为一句常量："**按 START.md 执行**。"

## 失效模式与对策

| 失效模式 | 对策 |
|---|---|
| 状态文字与代码漂移 | 只存不可推导的状态；现状永远以 `verify` 输出为准 |
| 长链误差累积 | 每轮全绿才交接，误差无法跨轮 |
| 上下文装不下 | 入口限定一页预算；日志只追加、定期归档 |
| 模型能力不足、卡住 | 任务按最弱模型切粒度；3 轮发散报警 |
| 规范被无视 | 规范即检查，由机器执行而非口头要求 |
| 并行冲突 | 默认串行；并行按模块边界切任务 |

# 验收标准

这套系统是否建成，只有一个判据：**把一个从未见过此项目的新模型指向仓库，只说一句"按 START.md 干活"，它能正确接力。** 如果还需要你口头补充任何背景，说明仓库里有该写下来而没写下来的东西——那才是唯一需要修的 bug。
