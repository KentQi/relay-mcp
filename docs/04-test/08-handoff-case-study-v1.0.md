# 多模型交接案例研究:证据比承诺更有说服力

本文不是功能宣传,而是一次**可复核的实测记录**:同一仓库在 2026-10-29 → 2026-11-09 期间,
由多个模型会话接力完成升级、修复与发布。所有数字都来自当场命令输出,读者可以按文末步骤复现同构场景。

## 1. 背景:为什么需要"证据型"交接

交接协议大多承诺"上下文不丢",但很少有可验证的判据。relay 的判据是可机检的四件东西:

1. **任务状态**(TASKS 的 `[ ]/[~]/[x]`)与 **LOG 完成条目**(`task=T### 完成`)一致(R9);
2. **出场绿闸**:结构检查 R1–R12 + 项目可执行验收,任一红则拒绝提交;
3. **事实底账**(R10):每条完成日志带机检段(文件数、增删行、base/sha、分支),可从 git 重算;
4. **成对证据**(受管 worktree):代码提交 SHA + 控制面提交 SHA,缺一不落完成。

下面的案例用这四条判据,记录了三次真实交接。

## 2. 案例一:跨版本升级(10-29 → 11-04)

- 起点:`v1.1.1`(本地 tag),目标:上游最新。
- 发现:上游已到 `v1.6.0`,期间合并了 worktree 生命周期(PR #1)、跨平台安装器(PR #3)、
  README 重写(PR #4)、裁判加固(PR #8)。**本地只落后 9 个提交时就开始动手,中途上游又前进了 64 个**——
  这正是"仓库即交接棒"要解决的问题:不靠聊天记录,靠 `git log` 与 CHANGELOG 就能追上。
- 交接产物:CHANGELOG 的 `[1.6.1]`、tag、本地 `git describe` 与 `package.json` 三者一致;
  安装器预检 `relay-mcp@1.6.1，14 个工具` 作为"服务真的换了版本"的独立证据。

## 3. 案例二:假绿事故(最有价值的一课)

### 现象

`npm test` 全绿,worktree 套件报告「107 通过 / 0 失败」。

### 反证

- 源码里 `L9-R08` 符号链接防线断言有 **9 条**;
- 运行日志里 `L9-R08` 出现 **0 次**;
- stderr 只有 git 的常规输出,**没有任何异常栈**;
- 实际执行断言数 = 107,恰好等于汇总数字。

结论:套件在符号链接夹具处抛 `EPERM` → 进入 `finally` → 打印绿色汇总 → `process.exit(0)`,
异常被吞,后半 48 条断言(含 7 条写穿防线)从未执行。

### 修复与回归

- 补 `catch` 显式判负;夹具建不出来时显式 `SKIP` 并计入汇总;
- 新增 `scripts/smoke-meta.mjs`:复现"无 catch + finally 内 exit"的坏套件并断言它确实假绿,
  再用静态规则扫描仓库内全部 `smoke-*.mjs`,要求同类形态必须配 `catch` 且 `catch` 递增 `fail`;
- 修复后同一套件报告「133 通过 / 0 失败 / 3 跳过」,SKIP 逐条说明原因(本机无符号链接特权),
  Linux CI 上 9 条断言全部真实执行。

**可复用的判据**:一个测试套件的"绿"必须能回答三个问题——跑了多少条?跳过了多少条?为什么跳?
答不上来的绿,不可信。

## 4. 案例三:外部质量门的编排(而不是内置)

- relay 核心零依赖、语言无关,不适合内置 CRAP/重复率/变异测试;
- `manifest.acceptance.commands` 是逐字符白名单:只有 `验收: test:<命令>` 行会执行,
  命中后经 shell 运行、超时 180 秒;命令非零退出 → 与测试失败同权,拒绝出场;
- 因此外部质量门(如 `crapper`、`dryer`、`mutator`)可以零代码接入,同时把信任边界留在人类手里
  (白名单条目 = 属主对一条命令的签字),relay 不自动安装、不自动升级。

这条设计让"质量门"成为**编排问题**而不是**依赖问题**——也正是 ub-mode 一类方法论能落地的前提。

## 5. 案例四:上下文预算作为机检项

- `tools/list` 是每个会话的固定成本。实测:14 个工具的描述 + schema 共 **14,919 字节(≈14.6 KB)**,
  粗估 5.5–7k tokens/会话;
- 其中约 40% 是与 `relay_rules` / `relay://protocol` 重复的规则条文。把条文搬回按需读取的载体、
  只留操作语义后,体积降到 **10,165 字节(≈9.9 KB)**,并新增 `smoke-budget.mjs` 断言 ≤10,240 字节;
- 同时守住"压缩不得伤可用性":每个工具仍保留"何时用 + 关键输入 + 返回什么",规则表仍完整可查。

## 6. 复现步骤

```sh
git clone https://github.com/KentQi/relay-mcp.git && cd relay-mcp
npm test                        # 20 套冒烟;关注每套的「通过 / 失败 / 跳过」三元组
node scripts/smoke-meta.mjs     # 元负控:假绿形态复现 + 静态规则
node scripts/smoke-budget.mjs   # tools/list 体积预算
node scripts/validate-plugin.mjs
relay relay_doctor --root .     # 环境七检(需先 npm i -g . 或用 node src/cli.mjs)
```

判读标准:

| 信号 | 可信 | 不可信 |
|---|---|---|
| 套件汇总 | 通过/失败/跳过三元组齐全 | 只有"全绿" |
| 出场 | verify 全量 + 验收命令真实执行 | 只跑结构检查 |
| 交接 | LOG 有负结果与事实行,可 `git log --grep` 反查 | 只有一句"已完成" |
| 版本 | tag / CHANGELOG / package.json / 预检握手一致 | 只说"已更新" |

## 7. 与"只有 AGENTS.md"的对照

| 维度 | 只有 AGENTS.md | relay |
|---|---|---|
| 上下文恢复 | 靠模型自己读文件,读到什么算什么 | `relay_session_start` 固定输出简报 + 下一步建议 |
| 完成判定 | 模型自述 | 绿闸 + 可执行验收 + 事实行 |
| 并发 | 无 | 认领锁 + 仓库写锁 + CAS 写入 |
| 失败 | 静默重试 | `修复:` 指令 + R7 停机 + 负结果进 LOG |
| 历史 | 无限增长 | R12 边界 + 归档指针 + recall/get 渐进披露 |
| 审计 | 不可回放 | 双提交 SHA + 机检事实段 |

结论:AGENTS.md 解决"模型知道规矩",relay 解决"规矩被执行、且可被陌生人复核"。
两者不是替代关系——本仓库的 `skills/relay-discipline` 正是把前者钉到后者的机检点上。
